# 棋友 長期ロードマップ

更新: 2026-11-15。**期間は目安ではなく段階**。ユーザーは「数日・数ヶ月・数年」かけることを許容しており、長期的な改善が前提。発売日や作業量を無根拠に確定しない。

| 段階 | 目的 | 主なID | 退出条件 |
| --- | --- | --- | --- |
| P0: 継承可能な基盤 | ソースと仕様の散逸を防ぎ、試作品を安全に維持 | KIF-001, KIF-002, KIF-003, KIF-050, KIF-061, KIF-062 | ClaudeとChatGPTが同じPublic GitHubソース・台帳を変更でき、Private Siteへのリリース経路が確認できる |
| P1: 本当に将棋を指せる | ルールとエンジンを信頼できる水準へ | KIF-010, KIF-011, KIF-020, KIF-021 | 基本合法性と規定した棋力・遅延のテストを通過 |
| P2: ライバルとしての個性 | 互角の強さ・人間的なミス・オールラウンドな戦型 | KIF-022, KIF-023 | 指定技量帯に対して自然で再現可能な対局経験を示す |
| P3: 本格教材 | 完全初心者から上級／有段までの体系と弱点連携 | KIF-030, KIF-031, KIF-032 | 教材の正しさと講義→練習→実戦→検討→復習の循環を検証 |
| P4: 共に成長する相棒 | 棋譜に根ざす自由会話・長期記憶・安全な同期 | KIF-040, KIF-041, KIF-050 | 会話の根拠、人格の一貫性、記憶管理・削除・バックアップが成立 |
| P5: 育ち続けるプロダクト | 有段者研究、イベント、性能・コスト・デザインの継続改善 | その時点でIDを追加 | ユーザー評価、棋力測定、教材効果に応じて更新できる運営状態 |

上記は機能の一本道ではない。例えばP1の間にも教材設計は進められる。ただし**精密な解説や実力保証は根拠となるエンジン・ルールが整うまで公開しない**。

## 最初に着手する順番の推奨

1. `KIF-001` と `KIF-002`・`KIF-062`: Public GitHubで共通の正本を確立。Private Siteの利用制限を保ち、公開前に機密と権利を点検。GitHub未整備でもテストや構想整理は続けられる。
2. `KIF-050` と `KIF-010`: 今ある棋譜を失わず、判定ミスの原因を早期に除去。
3. `KIF-020`: 既存のLv.4を延命させるだけでなく、将棋エンジン候補を評価。`KIF-021`へ。
4. `KIF-030`: 教材の技能マップを設計。強いエンジンが使えるようになったら問題検証を結合。
5. `KIF-022`・`KIF-023`: ただ強いだけではない棋友を実装。戦型の幅と人間らしさは独立した検証軸。
6. `KIF-040`・`KIF-041`: 自由会話と長期記憶を段階的に導入。最初は「確認できる過去棋譜について正しく話せる」を達成。

## 1スプリントの進行

- 「確認すべき仮説／解決するユーザーの不便」を一つ特定。
- `WORK_ITEMS.md` のIDと受入条件を確認、必要なら小さく分割。
- 実装＋テスト＋性能測定。モバイルUI変更ならスクリーンショット確認。
- 台帳に実測を残し、次の改善候補を更新。
- ユーザーの操作・評価が必要な場面でプレイしてもらい、主観的な棋力／人間味も評価する。

## 時間と予算の原則

外部の将棋エンジン・LLM・DB・CIにはそれぞれライセンス、CPU/GPU費用、利用規約がある。実際の料金・機能・制限は導入直前に公式の最新情報を検証し、月額上限をユーザーが決めるまで有料利用を始めない。
