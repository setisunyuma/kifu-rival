## 2. 技能マップ（初版）と進め方

技能は「分野＋番号」で識別し、`lib/lessons.ts`の`SKILLS`にデータとして持つ（前提の存在と非循環をテストで保証）。

| 分野 | 技能（ID） | 主な前提 |
| --- | --- | --- |
| A ルール | A1 駒の動き、A2 成り、A3 取る・持ち駒・打つ、A4 王手と詰み、A5 反則、A6 千日手・持将棋・入玉宣言 | A1→A2,A3→A4→A5、A6はA4 |
| B 損得と安全 | B1 駒の価値、B2 タダで取られない／取る、B3 両取り、B4 駒に紐を付ける | A3→B1→B2→B3,B4 |
| C 詰み | C1 1手詰、C2 3手詰、C3 5手詰、C4 7手以上 | A4,B2→C1→C2→C3→C4 |
| D 寄せ | D1 詰めろ、D2 必至、D3 囲い別の崩し | C2→D1→D2→D3 |
| E 受け | E1 王手の受け、E2 詰めろの受け、E3 凌ぎの手筋、E4 終盤の速度計算 | A4→E1、D1→E2→E3、D2,E2→E4 |
| F 手筋 | F1 歩、F2 大駒、F3 桂・香、F4 拠点 | B2→F1→F2,F3,F4 |
| G 序盤 | G1 序盤の原則、G2 囲い、G3 戦型（攻め形）、G4 定跡の狙い | B1→G1→G2→G3→G4 |
| H 形勢判断 | H1 4要素（駒の損得・玉の堅さ・駒の働き・手番）、H2 方針の決定 | B1,G2→H1→H2 |
| I 実戦と振り返り | I1 感想戦の進め方、I2 敗因の特定、I3 時間の使い方 | A4→I1→I2 |

**見直し候補（次の実装で反映）**: 「自分の弱点を理解し改善する能力」をI4（弱点の自覚と改善計画、前提I2）として独立させる。連盟のガイドラインを入手したら、C系列（詰将棋の手数の上げ方）とA〜Bの順序を照合する。

### 2.1 一律の順序か、並行か

| 案 | 長所 | 欠点 | 判断 |
| --- | --- | --- | --- |
| 一本道（級位ごとに全分野を順番に） | 分かりやすい | 得意分野で待たされ、苦手が後回しになる。実戦の必要と合わない | 退ける |
| 分野ごとに独立（自由選択） | 自由 | 前提を飛ばしやすく、詰将棋だけ・序盤だけに偏る | 退ける |
| **前提グラフ＋並行の3〜4系統** | 前提は守りつつ、詰み・損得と手筋・序盤・実戦を同時に少しずつ進める | 推薦の仕組みが要る | **採用**（現行の学習ループの前提制御がこれ） |

段級位は参考指標として扱い、技能ごとの習熟度と総合的な棋力（対局からの推定）は別に持つ。難しい教材へ進むこと自体は目的にしない。

## 3. 進級・補習・復習の設計

### 3.1 候補の比較

| 候補 | 何を確かめるか | 欠点 | 検証方法 | 判断 |
| --- | --- | --- | --- | --- |
| ① 同じ問題の解き直し | 記憶の保持 | 暗記で解ける。**これだけで習得と判定しない** | 1日後の正答率 | 補助として残す（現行の最小版） |
| ② 類似の別問題（転用問題） | 技能の転用 | 作問と品質保証の手間 | 未出題の転用問題での初回正答率 | **習熟判定の中心にする**（P2） |
| ③ 苦手分野への重点配分 | 弱点の解消 | 苦手ばかりだと意欲が落ちる | 苦手技能の正答率の推移 | 採用（1日の枠の1つを上限とする） |
| ④ 実戦の失敗に対応する推薦 | 実戦での発揮 | 失敗の自動判定が難しい | 推薦後の対局で同種の失敗が減るか | 自動判定できる失敗（1手詰・3手詰の見逃し、タダ取られ）から採用（P2） |
| ⑤ 前提不足に応じた補習 | 土台の欠落 | 原因の推定が外れることがある | 補習後に元の技能の正答率が上がるか | 採用（前提グラフをたどる） |
| ⑥ 習熟度に応じた新技能の推薦 | 適切な時期の新出 | 早すぎ・遅すぎの調整 | 新技能の初回正答率が極端でないか | 採用（現行の前提制御を、転用問題の結果で置き換える） |

### 3.2 指標

| 指標 | 使う場面 | 負担への配慮 |
| --- | --- | --- |
| 正答（初回の解答） | すべて | 既存の記録で足りる |
| 転用問題の正答 | 習熟判定 | 追加の操作はない |
| ヒントの使用 | 難易度の補正、習熟判定（ヒントありの正答は習熟に数えない） | 既存のヒントボタンを記録するだけ |
| 解答時間 | 当面は**記録のみ**。判定には使わない | 時間を競わせると焦りにつながる。外れ値（放置）も多い |
| 自己評価（「分かった／自信がない」） | 将来の候補 | 1タップ以内でなければ採用しない |

**習熟の初期仮説**: 「未出題の転用問題でヒントなしの正答が2回、1日以上の間隔を空けて」。数値は実測で調整する。

## 4. 教材の品質保証

**「正しい問題を出せる」ことと「今その生徒が解くべき問題を出せる」ことは別の品質要件**。前者は技術的品質、後者は教育的品質（教材そのものの価値）と推薦の品質（時期の適切さ）に分かれる。エンジンの評価値の正しさは技術的品質にしか関わらない。

### 4.1 技術的品質（機械で検証する）

| 層 | 内容 | 状態 |
| --- | --- | --- |
| L0 形式 | ID・技能タグ・出典・作成方法の必須項目 | 実装済み（PR #14） |
| L1 合法性 | 局面が正しく（`validatePosition`）、正解手が合法 | 実装済み |
| L2 正しさ | 取る／王手／詰みを実証。1手詰は全合法手から別解を検出 | 1手詰は実装済み。3・5手詰は**P1で実装** |
| L2' 最善性 | 詰み以外の問題で、エンジンのMultiPVの最善と次善の差を確認。エンジンの推奨と教材の意図が違う場合は、理由を解説に書くか問題を直す | KIF-021以降 |
| L2'' 解説の整合 | 解説に書いた手・駒・マスが盤面と一致するか（機械で読める形で手を書く） | P1で設計 |

### 4.2 教育的品質（人が評価する: L3）

機械の検証とは別の記録として、教材ごとに次を残す。初期はユーザーが評価に参加する（ADR-011後の指示）。ユーザーの確認だけで教育的品質が保証されるとは考えず、将来は指導経験者のレビューを加えられる形にする。

| 項目 | 内容 |
| --- | --- |
| 対象棋力 | 想定する棋力帯と前提技能 |
| 学習目的 | この問題で伸ばす技能と、解けた後に何ができるようになるか |
| 想定される誤解 | よくある誤答と、なぜ誤りかの説明 |
| 難易度の妥当性 | 想定と実測（正答率・ヒント使用）の差 |
| 転用 | 同じ狙いの別問題があるか |
| 修正履歴 | 変更点と理由 |
| レビュー担当者と確認日 | 誰がいつ何を確認したか |

### 4.3 推薦の品質（L4: 実測）

正答率・ヒント使用・転用問題の結果から、難易度と推薦の時期を補正する。1人の利用者では統計的な効果検証はできないため、仕組みが意図どおり働くことと、本人の実感・実戦の変化を分けて記録する。

## 5. 実装の優先順位（ユーザー指示の暫定順序との統合）

| 段階 | 内容 | 状態・理由 |
| --- | --- | --- |
| P0 安全なリリース準備 | PR #9（同期前の差分確定）、本書の資料修正 | 実施中。ほかの作業より先に、既存データを失わない道を作る |
| P1 正確性と教育的妥当性 | 3・5手詰の検証（詰み探索）、L3レビュー記録の形式、技能マップの見直し（I4） | 次に着手。**教材を増やす前に必要** |
| P2 個別最適化 | 対局記録からの弱点推定（見逃した詰み）、転用問題による習熟判定、補習・推薦の改善 | P1の詰み探索に依存（見逃しの判定に使う） |
| P3 AI対局 | YaneuraOu WASMの切り分け、ブラウザ実測、iPhone実測、棋力別の調整、対局後のフィードバック | 教材と独立して並行できる。iPhone実測はユーザーの協力待ち |

**順序の変更点**: P2の「対局記録からの弱点推定」は、P1の詰み探索ができれば低コストで作れる（1手・3手の詰みの見逃しを機械で判定できる）ので、P1の直後に置く。転用問題の作問はL3レビューの形式ができてから少数ずつ行う。

**退けた案**: 問題の大量追加を先に行う（品質保証がないまま誤りが広がる）、エンジンやLLMで問題を量産する（教育的価値の担保がない）、書籍の問題を収録する（著作権）、級位ごとの一本道（技能の偏りに対応できない）。

## 6. 初期検証の合格条件

- 仕組み（自動テスト）: 全教材がL0〜L2を通る。学習ループが「出題→回答→記録→復習予定→推薦」を正しく回す。
- 実戦（対局記録）: 1手詰・3手詰の見逃しの回数を、教材導入の前後で記録する。
- 本人の評価: 「今何を学ぶべきか分かる」「解いた内容を対局で使えた」の有無を感想として記録する。

## 7. 将来の拡張

戦型別の教材（G3・G4）は、エンジン接続（KIF-021）で狙いの説明を検証できるようになってから作る。有段者向けには、自分の棋譜からの問題化（自分の敗着を教材にする）と、戦型別の研究ノートを用意する。会話（KIF-040）とは、感想戦で技能タグを共有して結ぶ。

## 8. 残る不確実性・ユーザー判断
