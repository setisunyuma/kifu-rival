# 端末の記録の書き出し・復元（KIF-050）

更新: 2026-11-16。対象: 棋友の端末バックアップ実装。**この文書の作成は、本番の記録の取得・復元やSiteへの配備を行ったという意味ではない。** 配備前は、現在のSiteに以下の画面がまだない場合がある。その場合の退避手順は§6に記載する。

## 1. 何を保存するか

「成長の記録」画面の **「記録の持ち出しと復元」** から、その端末で棋友が保持している状態をJSONファイルに書き出す。

- 途中の対局の盤面・持ち駒・手番・手順・終局状態。
- 対局レベルと次の対局の入玉宣言規則。
- 対局記録、修了レッスンID、教材への回答記録。
- 回答時のヒント使用・初回回答の記録、既に回答した教材ID、回答前に使用したヒント。
- その端末の会話と、クラウド同期を停止しているかどうか。

**クラウドにだけ残っている記録や、別の端末の記録は含まれない。** この機能はD1データベース全体のバックアップではない。会話を含む個人の記録なので、本人が管理できる保存先を選ぶ。ファイルを公開リポジトリ、公開URL、レビューコメントへ添付しない。

端末の保存領域は、端末・ブラウザの保存領域・Siteのorigin（`https`などの方式、ホスト名、ポートの組）に結び付いている。同じアカウントで開いても、別のブラウザや別originに端末の記録が自動的に現れるわけではない。プレビュー環境の保存領域と本番Siteの保存領域も別に扱う。

## 2. 通常の利用手順

### 書き出す

1. 記録がある端末・ブラウザで棋友を開き、「成長の記録」へ進む。
2. 「記録の持ち出しと復元」の **「記録を書き出す」** を押す。
3. 検証が終わると `kiyu-backup-日時.json` のダウンロードが始まる。ブラウザやOSの保存先で、ファイルが実際に保存されたことを確認する。
4. アプリ内の成功表示はダウンロードを要求したことを表す。保存ダイアログの取消しやブラウザ側の制限まで検出するものではない。

通常の書き出しは、その時点の**画面内の状態**を検証して保存する。端末への自動保存に失敗していても、画面に残っている新しい状態を書き出すために使える。元の保存記録の読み込みに失敗した場合は、先に§4の「端末の保存内容を書き出す」で元データを退避する。

### 読み込み・確認・復元

1. まず現在の記録を書き出し、ファイルの保存を確認する。
2. **「ファイルを読み込む」** から復元したいJSONを選ぶ。ファイル全体の形式と棋譜を確認する間、端末の記録は置き換わらない。
3. 「復元する内容を確認」で、ファイル名、対局数、回答数、達成数、会話数、旧形式への対応などの注意表示を確認する。復元は現在の盤面や設定も含む**端末状態の置き換え**であり、現在の記録との自動マージではない。
4. 確認画面の **「復元前の記録を書き出す」** を押し、`kiyu-before-restore-日時.json` が保存されたことを確認する。この操作を行うまで復元ボタンは有効にならない。
5. **「この内容で復元する」** を押す。実際の置き換え直前の端末保存内容は、端末内にも1世代退避される。復元後はクラウド同期が停止する。
6. 復元した盤面、対局数、学習記録を確認する。その後ページを再読み込みし、同じ記録と同期停止状態が残ることを確かめる。再読み込みは復元を実行するためではなく、保存されたことを確かめる手順である。

確認画面の **「やめる」** は復元を行わず閉じる。別の画面へ移動した場合も確認は取り消される。確認中は対局AIを停止するが、確認を閉じると再開する。

確認中でも、先に始まっていたクラウドの読込みが完了する場合がある。復元を確定すると、その復元より前に始まった読込み結果は採用しない。手順4のファイルは書き出した時点の状態、端末内の1世代退避は実際に置き換える直前の保存内容であり、取得時点は同一とは限らない。

## 3. 復元後のクラウド同期

復元後の `cloudSyncPaused` は `true` として端末に保存され、再読み込み後も停止を維持する。この間、棋友からクラウドへの進捗送信とクラウド記録の追加読み込みを行わない。

再開する場合は、画面の **「同期を再開」** から確認内容を読み、明示的に再開する。再開するとクラウドにある対局・達成記録が端末に追加される場合がある。復元直後の状態を独立して残したい場合は、再開前にもファイルへ書き出す。

これは端末とクラウドを完全に一致させる同期ではない。特に、クラウドの会話をすべて端末へ戻す仕組みは未実装。端末バックアップの復元でクラウドの記録を削除・巻き戻しすることもない。

## 4. 読込みや保存に問題があるときの退避

「保存記録をそのまま退避する」を開くと、次の二つを選べる。

| ボタン | 読み出すもの | ファイル名 | 用途 |
| --- | --- | --- | --- |
| 端末の保存内容を書き出す | `kifu-rival.v1` に実際に保存されている文字列 | `kiyu-saved-raw-日時.json` | 通常の検証が通らない元データや、現在の保存内容を変更せず確保する |
| 直前の復元前データを書き出す | `kifu-rival.before-restore.v1` の文字列 | `kiyu-recovery-日時.json` | 直前の復元操作より前の端末保存内容を確保する |

この二つは内容をそのまま取り出すもので、正しい棋譜・完全なJSON・復元可能なファイルであることを保証しない。通常のバックアップ形式へ変換もしない。元データを調査・修復できるよう残すための機能であり、取得したファイルを読み込む際は通常と同じ検証を受ける。

### 直前の復元前に戻す

1. 「直前の復元前データを書き出す」で退避記録をファイルに保存する。
2. 現在の状態も「記録を書き出す」で保存する。
3. 手順1のファイルを「ファイルを読み込む」で選び、通常の確認・復元手順を行う。

端末内の退避は**1世代**で、次の復元前退避で置き換わる。複数世代を残す場合は、毎回ファイルとして保存する。退避キーがまだない場合は、その旨を表示する。

復元では、退避キーへの保存を先に行い、その後で現在の保存キーを置き換える。退避または置き換えに失敗した場合、アプリは復元完了として扱わない。端末容量などが原因の場合は、先にファイル退避を確認する。保存領域を空にする操作を復元の前提にしない。

元の保存記録の読み込みに失敗すると、元データを初期画面で上書きしないよう自動保存を停止する。自動保存に失敗した場合も画面内の状態は保持し、エラーを表示する。前者ではraw退避、後者では通常の書き出しも使い、必要に応じて両方を残す。

## 5. 読み込める形式・上限・互換性

通常のバックアップは `format: "kiyu-backup"`、`version: 1`、書き出した日時、端末状態を持つJSON。以前の `kifu-rival.v1` の値そのものも、対応する旧形式として読み込める。旧形式でも現在の対局 `game` は必要で、元から存在しなかった追加項目だけを初期値で補う。ヒント使用や初回回答が不明な旧記録を、初見・ヒントなしの正答として扱わない。

| 制限 | 現行値・扱い |
| --- | --- |
| JSONファイルの大きさ | UTF-8で5 MiB（5,242,880バイト）まで |
| 対局記録 | 1,000局まで |
| 1局または現在の対局の手順 | 2,000手まで |
| 検証する手数の合計 | 現在の対局と対局記録を合わせて100,000手まで |
| 教材への回答記録 | 20,000件まで |
| 会話 | 2,000件まで。1発話は20,000 UTF-16コード単位まで |
| 修了・既回答・回答前ヒントのID一覧 | 各20,000件まで |
| ファイルの検証・通常書き出し | Workerで実行。1回60秒で終了しなければ中止 |

上限を超えた場合は切り詰めずに処理を中止する。この上限以内でも、ブラウザの保存容量や端末性能によって保存・検証できない場合がある。表示する履歴の件数と、バックアップに保存する件数は別である。

未知の教材IDは記録として保持する。一方、未対応のフィールド、未知の将来バージョン、壊れた棋譜、終局後の余分な手などは取り込まず、元ファイルを保管するよう案内する。未対応フィールドを黙って削ってから復元することはない。

同一ID・同一内容の重複した対局は一件にまとめ、注意を表示する。同一IDなのに内容が異なる対局があるファイルは、どちらかを勝手に上書きせず取り込みを中止する。

Workerが使えない端末では、通常の検証や書き出しに失敗した旨を表示する。重い棋譜検証を画面処理へ移して続行することはない。raw退避は保存内容を直接読み出すため、別の経路として利用できる。

## 6. 初回Site配備前：旧SiteにバックアップUIがない場合

この節は、初回リリース前に**既存の保存値を読むだけで退避する手順**。新しい画面を使うために先にSiteを更新する必要はない。Siteのソース同期、配備、アクセス範囲変更、D1操作はこの手順に含めない。

### 6.1 保存元を取り違えない

1. 実際に棋友を使っていた端末とブラウザの保存領域で、現在の棋友Siteを開く。
2. 開いているページのoriginを確認する。GitHub、ローカル開発サーバー、別のプレビューURLで実行しても、本番Siteの端末保存内容は取得できない。
3. 同じSiteを複数の端末・ブラウザで使っていた場合は、必要な保存領域ごとに別々に退避する。
4. 対局や教材への回答など、保存内容を更新する操作を止めてから退避する。スクリプト自身はアプリの自動保存やクラウド通信を停止するものではない。

### 6.2 読み取り専用の退避スクリプト

対象ページのJavaScriptコンソールで次を一度実行する。ページに一時的な保存リンクが現れるので、**「棋友の保存内容をJSONで保存」** を押し、ファイルが保存されたことを確認してから「閉じる」を押す。

保存領域への操作は `localStorage.getItem('kifu-rival.v1')` 一回だけ。値の解析・再シリアライズ・更新・削除はしない。データ内容をコンソールへ表示せず、外部への送信も行わない。一時的なリンクの表示以外にページの状態を変更しない。

```javascript
(() => {
  let raw;
  try {
    raw = window.localStorage.getItem('kifu-rival.v1');
  } catch {
    window.alert('このページの保存領域を読み取れませんでした。設定や対象ページを確認してください。');
    return;
  }
  if (raw === null) {
    window.alert('この保存領域には棋友の記録がありません。使っていた端末・ブラウザ・Siteを確認してください。');
    return;
  }

  const stamp = new Date().toISOString().replace(/[:.]/g, '-');
  const filename = `kiyu-before-first-release-${stamp}.json`;
  const url = URL.createObjectURL(
    new Blob([raw], { type: 'application/json;charset=utf-8' })
  );
  const panel = document.createElement('div');
  panel.style.cssText = 'position:fixed;top:16px;left:16px;right:16px;z-index:2147483647;padding:16px;background:#fff;color:#111;border:2px solid #274c3d;font:16px/1.5 sans-serif;';
  const link = document.createElement('a');
  link.href = url;
  link.download = filename;
  link.textContent = '棋友の保存内容をJSONで保存';
  link.style.cssText = 'display:block;color:#174c35;text-decoration:underline;margin-bottom:12px;';
  const close = document.createElement('button');
  close.type = 'button';
  close.textContent = '閉じる';
  close.addEventListener('click', () => {
    URL.revokeObjectURL(url);
    panel.remove();
  }, { once: true });
  panel.append(link, close);
  document.body.appendChild(panel);
})();
```

ダウンロードが取消し・拒否された場合は、保存完了とはみなさない。記録がないと表示された場合も、空ファイルを新規バックアップとして作成しない。スクリプトは保存値をJSONとして修復しないため、破損した値もそのまま残せる。必要な修復は退避ファイルを確保してから別作業として行う。

このスクリプトが取るのは**読み取った瞬間の端末保存値**であり、まだ自動保存されていない画面の変更やD1全体ではない。本人の記録を画面キャプチャやログとして共有する必要はない。作業記録には、退避の成功・失敗、対象の保存領域、ファイル名、確認日時だけを残せばよい。

### 6.3 iPhoneから取得する場合の制約

iPhoneのSafariには、Macと同じ形で直接操作できる開発者コンソールはない。公式の経路は、iPhone側でWeb Inspectorを有効にし、MacのSafariから接続したiPhoneの対象ページを選んで調査する方法である。Mac側でも開発者向け機能を有効にする。設定画面の名称・配置はOSの版によって異なる。

Mac側で普通に同じURLを開くことと、**iPhoneで使っているページをリモート調査すること**は異なる。前者ではMacの保存領域を読む。ホーム画面へ追加したWebアプリを利用していた場合も、その利用中の保存領域を調査できているか確認する。

Macがない、端末の設定で調査できない、対象のアプリ内ブラウザが検査可能として公開されていない場合は、このコンソール手順を実行できたことにしない。実際に記録のある保存領域へアクセスできる環境を用意してから退避する。別のブラウザを新しく入れただけでは、元の保存領域の代わりにならない。

**この作業でiPhone実機の接続・ファイル保存は未実測。** 原典: [WebKit — Enabling Web Inspector](https://webkit.org/web-inspector/enabling-web-inspector/)、[Apple — Inspecting iOS and iPadOS](https://developer.apple.com/documentation/safari-developer-tools/inspecting-ios)（2026-11-16参照）。

## 7. 検証とリリース時の記録

実装の根拠は [バックアップの検証](../lib/backup.ts)、[バックアップ画面](../components/data-backup-panel.tsx)、[Worker経由の処理](../hooks/backup-task.ts)、[退避と置き換え](../lib/persistence.ts)。端末のデータ保全とSiteのリリース手順は別工程として記録する。

初回Site配備の前に、実データの退避ファイルを本人の管理下に確保する。配備後は、元の記録が残ること、通常書き出し・確認・復元・再読み込みで件数と盤面が保たれること、復元後の同期停止、意図的な同期再開、保存失敗時の表示を実際の対象端末で確認する。必要な本番操作は、そのリリースで承認された範囲に従う。

自動テストやPCのブラウザ確認を、iPhone実機での保存成功と置き換えない。未実測の項目は台帳に残し、個人データの中身をテスト結果や公開ログへ含めない。
