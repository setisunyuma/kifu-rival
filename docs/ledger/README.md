# 棋友 — 長期開発台帳（正本）

このディレクトリが**Claude CodeとChatGPTが共用する唯一の開発状態の正本**です。チャットの記憶・個人のメモ・未コミットの進捗報告では代替できません。長期間の停止や担当交替後にもここから再開します。

## ファイルと責務

| ファイル | 何を記録するか | 更新タイミング |
| --- | --- | --- |
| [WORK_ITEMS.md](WORK_ITEMS.md) | 一意のID、状態、受入条件、依存関係、検証証拠、次の一手 | **着手・完了・中断のたび** |
| [SESSION_LOG.md](SESSION_LOG.md) | 時系列の実作業、コミット、テスト結果、未完了の引継ぎ | **各作業セッション終了時**（追記式） |
| [DECISIONS.md](DECISIONS.md) | ユーザー承認済みの製品判断と未決の設計案を区別するADR | **重要な方針決定時** |
| [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md) | 承認・情報・技術検証が必要な問いと停止範囲 | 問いの発生・解決時 |
| [QUALITY_GATES.md](QUALITY_GATES.md) | 必須検証、証拠の形式、リリース判定 | 検証手順変更時 |

長期目標は [製品仕様](../PRODUCT_VISION.md)、実装実態は [構成](../ARCHITECTURE.md)、進行順は [開発ロードマップ](../ROADMAP.md)。いずれかが矛盾したら現物を確認して記録したうえで修正します。

## 状態語彙

- `BACKLOG`: 計画にあるが開始条件未整備
- `READY`: 受入条件と依存関係が整い着手可能
- `IN_PROGRESS`: 担当が作業中。未完了部分を明記
- `BLOCKED`: 権限・ユーザー判断・技術的な障害など明示的な阻害あり
- `VERIFIED`: 実装と受入条件が確認でき、結果への証拠がある
- `PARKED`: 意図的に当面保留。理由を記録

**別の意味の「完了」「ほぼ完成」などは状態として使用しません。** 複数の受入条件の一部を満たしただけなら `IN_PROGRESS` とします。検証不能なら `BLOCKED` か `IN_PROGRESS` のままです。

## 長期セッション・プロトコル

1. **再開**: `git status` → READMEとこの台帳 → 最後の `SESSION_LOG` → `OPEN_QUESTIONS` → 実コードの順に確認。開始時に意図したIDと現行コミットを記録。
2. **補完**: 情報が欠けていたら `不明／未検証` と記す。想像で埋めず、コード・テスト・公開設定から検出し、自力で安全に確認できる範囲を補完する。承認が必要なら止める。
3. **実装**: 受入条件・依存関係・テストを更新。データ移行や費用は人間の承認条件に従う。
4. **検証**: [QUALITY_GATES.md](QUALITY_GATES.md) の必要条件を満たし、コマンドと結果・実機確認を残す。
5. **引継ぎ**: 途中でも再開地点を `WORK_ITEMS` の `Next` と `SESSION_LOG` の最後に必ず残す。コミットがない作業は別担当へ引き継がれていないとみなす。
6. **監査**: `npm run ledger:check` を実行。これは形式検査であり、内容の真偽を保証しない。

## IDと所有権

`KIF-xxx` は作業ID、`ADR-xxx` は設計判断、`Q-xxx` は未決事項。IDは変更・再利用禁止。`Owner` は担当者ではなく、当該作業を前進させる責任の所在（`Claude`/`ChatGPT`/`User`/`Unassigned`）。変更者は`SESSION_LOG`に記名し、完了の証拠を明記する。

**将来新しいAIや開発チャンネルを作っても、最初にこの台帳を読ませる。** 新たな散在台帳を勝手に正本にしない。
