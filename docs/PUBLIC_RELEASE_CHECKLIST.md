# Public GitHubソース公開チェックリスト

更新: 2026-11-15。**GitHubリポジトリの公開方針はPublic、ChatGPT Sitesの実行アプリは本人限定のPrivate**（ADR-007）。GitHubの作成・移管は別作業であり、両者は自動的には同期しない。

## 公開前に満たす条件

1. `npm run public:check` で、Gitに追跡されたファイル名とテキスト中の典型的な鍵・トークン・個人メールを静的検査する。**検査のPASSは機密情報ゼロの証明ではない**。
2. `git ls-files` と `git log --format='%an <%ae>'` を人間または担当AIが確認する。履歴を丸ごと公開する場合、**過去の全コミットと削除済みファイル**も別途検査する。安全な履歴が未確認なら、GitHub移管時は**検査済みの現在のスナップショットのみ**から新履歴を開始する。
3. ChatGPT Sitesの実行用 `.openai/hosting.json` はプロジェクト識別子を含み、`README.md` 等には試作SiteのURLが載っている。これらは鍵ではないが、**Publicでは閲覧可能になる**ことを認識する。APIトークンや本人の認証・許可設定はソースへ含めない。
4. 実利用者の棋譜・会話、D1ダンプ、ブラウザのlocalStorage、個人情報をサンプルデータと混同して追加しない。テストには架空データのみ使う。
5. ソースのPublic公開と、アプリ自体の公開を分離する。Site側の `access_mode=custom`、本人のみ許可・外部来訪者0、を操作前後に確認する。GitHubへpushするだけでSiteがPublicになるわけではない。
6. GitHub Actionsはリポジトリ公開時に外部PRのコードを実行し得る。`pull_request` イベントは読取専用、CIへデプロイ鍵・Site資格情報・本番DBトークンを渡さない。`pull_request_target` で外部コードを実行しない。
7. エンジン、評価関数、定跡、教材、駒画像・フォントなど第三者製作物は**それぞれの権利条件**を確認。Publicになったからといって第三者コードを自由に再配布してよいわけではない。
8. プロジェクト自身の再利用条件を定めるルート `LICENSE` は現時点で**未決**（Q-008）。Publicは閲覧可能という意味であり、それ自体がオープンソースライセンス付与ではない。ライセンス採用はオーナー判断。

## チェックの記録

公開に使用するGit SHA、検査日、対象（最新スナップショット／全Git履歴）、検出件数、本人限定Siteの確認、未確認項目を `docs/ledger/SESSION_LOG.md` に残す。

## 責務

- **KIF-062**: 公開ファイルの自動・手動監査、検査の保守。
- **KIF-002**: Public GitHubリポジトリ作成とソース移管、Claudeがcloneできる確認。
- **KIF-003**: GitHubとPrivate Sitesの同期・本番リリース経路。

GitHubの`Public`設定はユーザー承認済みだが、公開操作の完了が確認できるまで `KIF-002` を `VERIFIED` にしない。
