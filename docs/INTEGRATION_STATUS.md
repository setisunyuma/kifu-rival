開発版のエンジンはリポジトリ外の配布物を開発サーバーだけが配信する。`npm run build`の成果物とSiteにはエンジンも配信経路も含まれず、Siteでは「この環境には強いエンジンが入っていません」と表示して内蔵AI（Lv.1〜4）で対局できる。

### 開発版の起動手順

```sh
engine_lab=$(mktemp -d)   # リポジトリの外
npm pack fairy-stockfish-nnue.wasm@1.1.12 --ignore-scripts --pack-destination "$engine_lab"
tar -xzf "$engine_lab/fairy-stockfish-nnue.wasm-1.1.12.tgz" -C "$engine_lab"
KIFU_ENGINE_DIR="$engine_lab/package" npm run dev   # http://127.0.0.1:5173/
```

`KIFU_ENGINE_DIR`がリポジトリ内を指すと起動を拒否する。設定時だけ、開発サーバーの全ページにCOOP/COEP（`same-origin`/`require-corp`）を付ける。

## 3. 初回リリースの判定と準備

PR #9の`scripts/release.mjs plan`を、本PRのheadと現在の`main`の差分に対して実行した結果は **`data`**（承認・バックアップ・巻き戻し計画が必要）。理由:

- `lib/persistence.ts`・`app/rival-app.tsx`: 端末保存キー`kifu-rival.v1`の書込み処理の移動と変更。保存内容は回答・会話の件数を切り詰めずに保存する形へ変わる（PR #22）。
- `components/data-backup-panel.tsx`: 保存内容の読取り（退避用）。
- `hooks/use-engine-rival.ts`: 開発版の対局相手設定を別キー`kifu-rival.engine-dev.v1`へ保存（本PR）。
- `vite.config.ts`・`scripts/vite/engine-*.{js,mjs}`: 開発サーバーのみの変更だが、ビルド設定の変更として`runtime`。

**本当の基準は「現在Siteで動いている版」であり、`main`ではない。** Siteの現在の版をGitHubのどのコミットに対応づけるかは本人の確認が必要（PR #9 `docs/RELEASE.md`の手順1）。

data判定のリリースに必要なもの（PR #9の手動ゲート`APPROVAL_FIELDS`）:

1. `approvedBy`・`approvedOn`・`scope`: 本人の承認。
2. `d1Backup`: D1のバックアップ（Siteの管理画面または手順の確認が必要）。
3. `deviceDataBackup`: **記録がある端末・ブラウザで、現在のSiteから記録を退避したファイル**。現在のSiteにはPR #22の書き出し画面がないため、`docs/BACKUP_RESTORE.md` §6の読み取り専用手順を使う。PR #22の機能が完成していることは、この退避が済んだことを意味しない。
4. `rollbackPlan`: 旧版へ戻すと、新しい版が保存した回答・会話の件数（旧版の上限を超えた分）を旧版が再保存時に切り詰める可能性がある（PR #9の文書に記載）。戻す前に新版で書き出したファイルを保管する。
