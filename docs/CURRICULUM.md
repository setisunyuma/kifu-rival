## 2. 技能マップ（初版）

技能は「分野＋番号」で識別する。**一本道ではなく**、分野ごとに並行して進め、前提だけを依存関係として持つ。

| 分野 | 技能（ID） | 主な前提 |
| --- | --- | --- |
| A ルール | A1 駒の動き、A2 成り、A3 取る・持ち駒・打つ、A4 王手と詰み、A5 反則（二歩・打ち歩詰め・行き所のない駒）、A6 千日手・持将棋・入玉宣言 | A1→A2,A3→A4→A5、A6はA4 |
| B 損得と安全 | B1 駒の価値、B2 タダで取られない／取る、B3 両取り、B4 駒に紐を付ける | A3→B1→B2→B3,B4 |
| C 詰み | C1 1手詰、C2 3手詰、C3 5手詰、C4 7手以上 | A4,B2→C1→C2→C3→C4 |
| D 寄せ | D1 詰めろ、D2 必至、D3 囲い別の崩し（美濃・矢倉・穴熊） | C2→D1→D2→D3 |
| E 受け | E1 王手の受け（合駒・逃げる方向）、E2 詰めろの受け、E3 凌ぎの手筋、E4 終盤の速度計算 | A4→E1、D1→E2→E3、D2,E2→E4 |
| F 手筋 | F1 歩の手筋（突き捨て・垂れ歩・継ぎ歩・合わせ）、F2 大駒の手筋、F3 桂香の手筋、F4 拠点 | B2→F1、F1→F2,F3,F4 |
| G 序盤 | G1 序盤の原則（玉を囲う・大駒を使う）、G2 囲い、G3 戦型（居飛車の銀・振り飛車）、G4 定跡の狙いの理解 | B1→G1→G2→G3→G4 |
| H 形勢判断 | H1 4要素（駒の損得・玉の堅さ・駒の働き・手番）、H2 方針の決定 | B1,G2→H1→H2 |
| I 実戦と振り返り | I1 感想戦の進め方、I2 敗因の特定、I3 時間の使い方 | A4→I1→I2 |

**段階（棋力帯）の目安**: 入門（ルール）→ 15〜10級 → 9〜5級 → 4〜1級 → 初段 → 有段。帯は「この帯で主に練習する技能」の目安で、出題の制限には使わない。例: 9〜5級の中心はC2・B3・E1・F1・G2・I1。

**棋力と技能を分ける**: 棋力（レーティング）は対局結果から推定し、技能の習熟度は技能ごとに持つ。初段相当の棋力でも受け（E）が弱い、という状態を表現できるようにする。

## 3. 進級・補習・復習

| 論点 | 比較した案 | 推奨（初期仮説） |
| --- | --- | --- |
| 習熟の判定 | (a) 正答率だけ (b) 正答率＋時間 (c) **初見の転用問題での正答＋日を空けた再確認＋実戦での発揮** | (c)。目安は「初見の転用問題で8割、1日以上空けて2回」。実戦での発揮は対局記録から自動推定できる技能だけ（例: 1手詰の見逃し）から始める |
| 復習 | (a) 固定周期 (b) SM-2等の間隔反復 (c) **段階式（1日→3日→7日→21日）** | (c)。説明しやすく、テストしやすい。データがたまったら(b)を比較する |
| 配分 | (a) 詰将棋中心 (b) 均等 (c) **新規・復習・弱点の3枠に分け、弱点を重み付け** | (c)。1日の目安は新規1・復習1・弱点1の3問（初期値、調整対象） |
| 補習 | (a) 同じ問題を再出題 (b) **前提技能へ戻り、転用問題で再確認** | (b)。同じ問題の再出題は暗記で解けるため判定に使わない |
| 段階の解放 | (a) 正答数で解放 (b) **前提技能の習熟で解放**、ただし先の教材の閲覧は常に可能 | (b)。難しくすること自体を目的にしない |

## 4. 教材の品質保証

**エンジンの評価値が正しいことと、教育的に良い問題であることは別**。自動検証は「正しさ」を、人の評価は「教える価値」を担当する。

| 層 | 内容 | 担当 | 状態 |
| --- | --- | --- | --- |
| L0 形式 | ID・技能タグ・出典・作成方法・ライセンスの必須項目 | 自動（テスト） | 実装済み（P1、PR #14） |
| L1 合法性 | 局面が`validatePosition`で問題なし、正解手が合法 | 自動 | 実装済み（P1） |
| L2 正しさ | 詰将棋は**全合法手を調べて詰む手を列挙**し、別解の有無を記録。別解がある問題は「正解に含める」か「局面を直す」 | 自動 | 1手詰は実装済み（P1）。3手詰以上は次段（P2） |
| L2' 最善性 | 詰み以外の問題はエンジンのMultiPVで最善手と次善手の差を確認（差が小さい問題は採用しない） | 自動（KIF-021以降） | 未 |
| L3 教育的評価 | 技能タグが合っているか、解説が正しいか、誤答の解説があるか、難易度と前提が妥当か | 人（ユーザー・ChatGPT・Claudeの相互確認） | チェックリストを用意 |
| L4 実測 | 正答率・所要時間・ヒント使用から難易度を補正 | 自動集計（KIF-032） | 未 |

**転用問題**: 1つの技能には、同じ狙いで盤面が違う問題を複数用意する。判定には未出題の問題を使う。

**出典の記録**: 全教材に`source`（`original`＝棋友オリジナル）、作成者、作成方法、検証方法を持たせる。書籍・他サイトの問題は使わない。

## 6. 初期検証の合格条件

利用者が1人のため、統計的な効果検証はできない。**仕組みが正しく働くこと**と、**本人の実感・実戦の変化**を分けて確認する。

- 仕組み（自動テスト）: 全教材がL0〜L2を通る。学習ループが「出題→回答→記録→復習予定→解放」を正しく回す（P4の受入条件）。
- 実戦（対局記録）: 1手詰・3手詰を見逃した回数を、教材導入の前後で記録する。
- 本人の評価: 「今何を学ぶべきか分かる」「解いた内容を対局で使えた」の有無を、感想として記録する。

## 7. 将来の拡張

戦型別の教材（G3・G4）は、エンジン接続（KIF-021）後に「狙いの説明」を検証できるようになってから作る。有段者向けには、自分の棋譜からの問題化（自分の敗着を教材にする）と、戦型別の研究ノートを用意する。会話（KIF-040）とは、感想戦の振り返りで技能タグを共有して結ぶ。

## 8. 残る不確実性・ユーザー判断

1. SiteにGitHubにない教材・機能があるか（指示書の「教材10件」「日課出題」）。あれば先にGitHubへ取り込む。
2. 教材の教育的評価（L3）を誰が行うか。初期はユーザー本人の確認を推奨。
3. 1日の出題数・復習間隔などの初期値（上記は仮説）。
