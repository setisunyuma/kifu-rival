# 品質ゲートと検証の証拠

`npm run ledger:check` は台帳の**形式**だけ確認する。棋力やバグの少なさを保証しない。

## 全変更に必須

- `git diff --check`（無意図な空白・衝突マーカーを確認）
- `npm run ledger:check`
- `npm run public:check`（GitHub Publicソースの追跡ファイル点検。過去Git履歴・バイナリ・未追跡ファイルは別途確認）
- `npm run test:unit`
- `npm run lint`
- `npx tsc --noEmit`
- `npm run build`（Sites環境ではSitesスキルの推奨build経路に従う）
- テスト結果の成功/失敗/未実施を `SESSION_LOG` に記録。**未実施=成功ではない。**

## 変更内容に応じて追加

| 変更対象 | 追加ゲート | 保存する証拠 |
| --- | --- | --- |
| 盤・駒・UI | 幅320/375/390/430px、Safari/iPhone、成り・持ち駒・選択・スクロールを実機または適切なブラウザで確認 | 対象幅、スクリーンショット、実施/未実施 |
| ルール／棋譜 | 既知局面と合法手、打ち歩詰め、千日手等を検証。入力/出力の往復テスト | 局面ID、実測値、テスト名 |
| エンジン／棋力 | ランダム性を固定できる評価ケース、複数局の棋力測定、失着・処理時間の記録 | 条件（端末・制限時間・相手・手数）、結果 |
| 教材 | 全問題の局面と模範手を検証し、解説をレビュー | 問題ID、検証エンジン／レビュー記録 |
| 会話／記憶 | 棋譜・勝敗の取り違えがないこと、誤回答ケース、データ開示・消去 | 例題、期待応答、結果。実個人会話はログへ転載しない |
| DB／認証 | 既存データの後方互換性、本人以外への漏えい防止、ロールバック | 影響スキーマ、移行テスト、バックアップ手順 |
| OSSエンジン・データ | 原典のライセンス、結合/配布方式、重み・定跡等の個別権利 | 対象SHA／ライセンスURL／配布対象／レビュー記録 |
| GitHub Publicへの初回移管 | 個人データ・鍵・Git履歴・画像の権利・無Secrets CI、SiteがPrivateか | 公開するソースSHAとスキャン結果、実行Siteの許可範囲、未確認点 |
| PR自動マージ | read-only CI成功、実行元・本人/同一repo・head/base一致、許可ファイル・差分上限、`main` ruleset | `Guarded auto-merge`のGitHub run URLとマージSHA、または拒否理由のログ。未実施は未実施と記す |
| リリース | privateアクセス、動作確認、公開済みversionとソースcommitの対応 | URL・バージョン・git SHA・検証時間 |

## 完了を名乗る前の質問

1. `WORK_ITEMS` の受入条件はすべて満たしたか。
2. 記載した機能は本当にコードへ反映され、テストしたか。
3. ユーザーデータや秘密情報・外部公開・費用への影響は何か。
4. 依存タスク・ユーザー判断を未承認のまま飛び越えていないか。
5. 途中で引き継いでも、再現手順・次の一手は明瞭か。

いずれかにNoまたはUnknownなら `VERIFIED` を使用しない。
